# 02. Competitor model: beating the modal LLM pitch

Written 2026-08-31. Premise: in SIH 2025 there were 72,165 idea submissions across 271 PS (avg 266 per PS, newsonair.gov.in, fetched 2026-08-31). In 2026 assume most of those decks are LLM-drafted. The thing to beat is not the other teams' effort, it is the modal output of the same model everyone is prompting. ASSUMED: no survey of LLM usage among SIH teams exists; the premise rests on 2026 base rates of student LLM use.

## 1. The median AI-assisted pitch, predicted concretely

Write the prompt a competing team uses: "Here is SIH PS 260XX [pasted title]. Make me a winning 6-slide SIH idea PPT." The model returns, with high confidence, this deck:

- Slide 2: "AI-powered unified platform" restating the PS title as a solution. 4 bullet features. The phrase "real-time" appears 2+ times.
- Slide 3: React or Next.js dashboard, Flutter citizen app, Python FastAPI backend, a RAG chatbot over ministry PDFs, one ML model chosen by data type (YOLO if images, LSTM or Prophet if time series, random forest otherwise), Bhashini or Google Translate for "22 languages", AWS or GCP icons, a microservices box diagram with 8-12 boxes.
- Slide 4: "uses proven open-source technology, highly scalable". Risks: "data privacy, user adoption". Mitigations: "encryption, awareness workshops".
- Slide 5: SDG icons, "reduces processing time by 80%", "benefits 1.4 billion citizens", no baseline, no source.
- Slide 6: 2 news links and a Kaggle dataset nobody on the team has opened.

Tells that give it away in a 30-second skim: mocked screenshots, no named legacy system or form number, no number with a source, a technology list optimised for breadth, risks that apply to any project on earth.

Variant decks by PS type, still modal: for anything agricultural, add a drone and NDVI; for anything medical, add "federated learning for privacy"; for anything document-heavy, the deck IS a RAG chatbot; for anything geospatial, a Leaflet map with mock pins.

This prediction is the point: if our deck could have been generated by that prompt, we have not entered the competition yet.

## 2. Axes where the modal pitch cannot compete

Tested against the Phase 1 evidence (failure modes and finale mechanics in `01-event-model.md`) and kept only where they map to something evaluators demonstrably score.

Given axes, all confirmed useful:
- A. Real data already in hand, named source, shown live, versus a mocked screenshot. Maps to failure mode 2 (prototype) and the slide 3 field label inviting a working prototype at idea stage.
- B. A hard constraint actually solved: offline-first, sub-2G bandwidth, edge device, sub-100ms latency, cost per query at scale, low-resource language, air-gapped deployment. The modal deck lists technologies; it never satisfies a constraint, because constraints require engineering choices an LLM will not commit to unprompted.
- C. A measured baseline and a number that beats it, versus "improves efficiency". Maps to failure mode 1, the most-cited loss reason (weak cost or measurable-impact answer, 3 first-hand sources).
- D. Domain depth a generalist team cannot fake: DSP, orbital mechanics, RF, EDA, control loops, geospatial pipelines, actual statute text. At the finale, 3 mentoring + 3 evaluation rounds interrogate depth; a bluffed domain collapses in round 2.
- E. An artifact that already exists and runs. Converts the December finale from a 3-week gamble into iteration on something real; also the strongest possible slide 3.
- F. A deployment path a ministry could sign off: NIC or MeghRaj hosting, DPDP Act compliance, integration with the named existing system (eOffice, PM Gati Shakti, DIKSHA, existing departmental MIS), not a new parallel platform. Maps to the purpose model: the sponsor paid Rs 1.95L+ to get something usable.

My additions:
- G. Solve the PS body, not the PS title. The body names the real workflow, the forms, the legacy software, sometimes the dataset. The modal pitch is generated from the title. Reading comprehension is an edge: failure mode 3 ("not reading the full problem statement") is cited by 2 guides + 1 first-hand.
- H. An evaluation protocol, not an accuracy claim. State the held-out test, the metric, the baseline to beat, and what number we currently get. No modal deck proposes falsifiable measurement. This also pre-arms the finale's scored rounds.
- I. Unit economics at government scale, stated and defended: cost per query, per device, per school, per district, with the arithmetic shown. Directly answers the most-cited loss reason.
- J. An honest slide 4: our 3 real failure modes with the mitigation we already tested, versus 3 generic risks. A screener who has read 200 identical risk slides notices the one that bleeds.

Axis interaction worth exploiting: A + E + H compound. Real data, running artifact, measured number produces a slide 2 sentence no LLM will generate: "We already ran it: X on dataset Y, beating baseline Z by N%."

## 3. The single strongest anti-consensus heuristic

Pick the PS whose body text names a concrete dataset, workflow or legacy system, then pitch the boring tool that measurably beats the named baseline, because every LLM-assisted team is pitching a platform at the title.

Runner-up heuristic, kept for Phase 5 use: prefer a PS where the demo's one number can be measured before submission (axis H feasible in 2 weeks), because "we already measured it" is the cheapest unfakeable signal available at idea stage.
